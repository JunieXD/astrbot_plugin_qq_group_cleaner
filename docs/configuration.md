# 配置说明

配置只有三部分：总开关、每个群的规则、共用的执行节奏。平时只需修改群号、人数和未发言天数。更改配置后在 AstrBot 保存并重载插件，旧计划会失效。

## 每个群

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| 检查这个群 | 开 | 是否纳入定时检查；还需打开总开关 |
| 运行方式 | 仅预览 | 仅预览、确认后清理、自动清理 |
| 开始人数 | 490 | 人数达到此值才开始，不能超过实际容量 |
| 停止人数 | 470 | 必须低于开始人数；达到后停止 |
| 未发言天数 | 90 | 至少 7 天；最后发言、入群和本地观察到的活动取最新时间 |
| 新成员保护天数 | 30 | 至少 7 天；保护刚加入的人 |
| 先清理谁 | 最久未发言优先 | 在符合全部条件的候选中排序 |
| 综合排序权重 | 未发言70、群等级30、QQ等级0 | 只对综合排序生效；0不参与，无需凑满100 |
| 群等级保护线 | 0 | 0 关闭；例如 10 表示等级≥10就保护 |
| 始终保留的 QQ | 空 | 每项一个 QQ，不用重复填写群主或管理员 |

人数达到开始线后形成一个清理周期，分批降至目标；中间自然退群也会减少需要清理的人数。周期最长 7 天，超过后需要重新达到开始线。配置改变后重新判断。

群号不可重复。开始/停止人数、天数、延迟等不合法时，插件明确指出配置位置并停止加载，不偷偷换成另一个值。

## 清理顺序

| 选项 | 优先级从左到右 |
| --- | --- |
| 最久未发言优先 | 最近活动时间由早到晚 |
| 群等级低优先 | 群等级由低到高 → 最近活动由早到晚 |
| QQ等级低优先 | QQ 等级由低到高 → 最近活动由早到晚 |
| 综合排序 | 加权得分由高到低 → 最近活动由早到晚 → QQ号 |
| 自定义 | 使用你填写的顺序；最后用 QQ 号稳定排序 |

自定义可逐项填写：`群等级`、`QQ等级`、`未发言天数`、`未发言时长档位`、`入群时间`。自定义中的时长档位为90、180、365天；同一档内比较下一项。入群时间由早到晚排序。

例：“群等级低且长时间未发言，而且 QQ 等级也低”：未发言 90 天；“更多条件”中群等级上限 3、QQ 等级上限 20；顺序选群等级低优先。三个条件同时满足才成为候选。如果只希望 QQ 等级参与排序，不要设置 QQ 等级上限。

综合排序使用公开、固定的评分规则，其余顺序使用明确的逐项排序；都不调用LLM。

## 综合排序怎样计分

默认 **未发言时长70、群等级30、QQ等级0**。权重越大，越看重这一项；填写7、3、0与70、30、0效果相同。每项可填0～100，选择综合排序时至少一项大于0。预览和“解释”会显示0～100的综合得分，分数越高越优先。

先检查全部保护和候选条件，再计算得分。高分不会绕过未发言天数、新成员保护、管理员、名单、等级保护、头衔或禁言保护；评分本身也不会新增一个清理门槛。

内部公式固定，不需要用户配置归一化参数：

- 未发言分：超过“至少未发言天数”的部分，每多一天增加，额外满180天计100分，更久封顶。
- 群等级分：`max(0, 100 - 群等级)`。
- QQ等级分：`max(0, 100 - QQ等级)`。
- 综合得分：各项分数乘权重后求和，再除以权重之和。同分优先更久未发言，最后以QQ号稳定排序；排序使用完整精度，界面显示一位小数。

例如未发言门槛30天、权重70/30/0时：170天未发言且群等级70，得分63.4；90天未发言且群等级10，得分50.3。前者优先，说明群等级和未发言时间可以相互权衡。

权重0的项不参与评分，也不为该项补查候选资料。默认不需要QQ等级，因此等级未知不会仅因评分被排除。**独立条件仍生效**：即使QQ权重为0，设置了QQ等级上限仍需要补查；群等级权重为0但开启了群等级保护/上限时，群等级仍必须有效。开启的维度缺失时保留成员，不把未知值当低等级，也不临时把权重分摊到其他项。

v0.2.0将原“综合排序”改为加权评分，已有配置未填写权重时采用70/30/0，更新重载后旧计划失效。若需要原来的顺序，选择“自定义”，依次填写“未发言时长档位、群等级、QQ等级、未发言天数”。

## 更多条件（可以不填）

| 配置 | 默认 | 含义 |
| --- | --- | --- |
| 候选最高群等级 | 0 | 0 不限；正数表示只考虑≤该等级的人 |
| 候选最高 QQ 等级 | 0 | 同上；资料缺失不满足条件 |
| 保留专属头衔成员 | 开 | 头衔存在即保留；不能用接口固定的到期值判断过期 |
| 保留被禁言成员 | 开 | 避免把无法发言的人当作不活跃；状态不明也保留；全员禁言时暂缓整群清理 |
| 自定义顺序 | 空 | 选择自定义时填写；不能重复 |
| 机器人 QQ | 空 | 单 QQ 自动识别，多 QQ 接入才需要填写 |

所有开启的条件是“同时满足”。保护优先于候选条件，候选条件优先于排序。不提供任意布尔表达式编辑器，避免配置难以理解。

接口明确返回的群等级 `0`（数字或字符串）按有效的 0 级处理，正常参与等级上限、保护线和排序；综合评分中的群等级分为100，再乘对应权重。0级不会自动成为清理对象，仍须满足未发言天数、新成员保护等全部规则，也不额外要求“最后发言时间等于入群时间”。

群等级字段缺失、空值、负数等无效数据仍视为未知。QQ 等级 `0` 仍视为待补查，避免将未加载的账号资料当低等级。规则依赖某种等级时，该等级未知的成员受到保留；不依赖时，不因缺失等级妨碍其他规则。

QQ 等级每轮最多补查 20 人，候选资料缓存 7 天并绑定本次入群身份。在还存在未尝试补查的候选时不生成执行名单。全部尝试过后，对有效资料排序，仍然未知的成员保留。成功补查逐人保存进度，单个成员查询失败会暂时保留此人并缓存失败6小时，其他进度不会丢失。每次真正移出前再次查详情，缓存不能代替最后核验。

## 执行节奏

| 配置 | 默认 | 可填范围 |
| --- | --- | --- |
| 每批人数 | 5 | 1～10 |
| 每群最近 24 小时上限 | 20 | 1～100 |
| 每账号最近 24 小时上限 | 30 | 1～100；本插件各群合计 |
| 群内批次间隔 | 60 分钟 | 30～1440 |
| 每人操作前随机等待 | 30～90 秒 | 各 10～600；最小≤最大 |
| 普通启动/重载缓冲 | 30～90 秒 | 各 0～600；最小≤最大；都填0可关闭这项缓冲 |
| 连接或异常恢复冷却 | 300～900 秒（5～15分钟） | 各 30～3600；最小≤最大 |
| 每天允许执行时段 | 09:00～22:00 | 北京时间；0～24 全天，22～6 跨午夜 |

普通启动或保存配置后的重载只使用短缓冲，连接正常时不会额外触发恢复冷却。检测到断线重连、网络异常，或管理员使用“恢复”命令时，使用恢复冷却。两组参数位于“执行节奏”，单位均为秒；留默认值即可。自动检查会先等待启动缓冲结束；手动预览在连接就绪后可以进行，恢复冷却和批次间隔继续阻止实际移出。

启动缓冲结束后，如果 QQ 接入还未加载、NapCat 尚未连接或 QQ 显示离线，自动检查约30秒后重试，不会因启动顺序误报多账号冲突并等待一小时。接口故障、真正的账号绑定冲突及其他检查错误仍按原有保护处理。

“状态”、恢复命令回复和等待日志会说明正在等待普通启动缓冲、连接/异常恢复还是批次间隔，并显示北京时间截止时间。到时仍要满足执行时段、额度、共享队列和每人随机等待，且重新核验资料；异常暂停和结果不明不会因等待结束而自动解除。

已记录的等待截止时间不会因重载、缩短配置或重复“恢复”而提前；新值用于之后的新等待。升级时若旧版5～15分钟启动等待尚未结束，本次仍会保留原截止时间。观察到的离线状态和连接恢复冷却持久保存，避免重载抹掉恢复保护；无法观察到的断线仍不能可靠识别。

上限统计已提交请求，包括超时和结果不明。配额按滚动 24 小时计算，不是午夜清零。暂停、恢复、更新和重载均不清零。

确认计划有效 30 分钟。如果在有效期内无法满足时段、额度、批次间隔，计划过期，需要重新预览确认。手动确认不绕过任何等待条件。自动模式下一次检查自行生成新计划。

未暴露的内部限制：约 30～35 分钟检查一次，每个接入每小时最多 180 次读取（跨重载保留，后台最多使用120次，其余分别留给执行复核和管理员命令），读取间隔 1.5～3 秒；普通检查错误后等待1小时再试。上述等待均是工程上的请求节奏控制，不是已验证的 QQ 安全频率；NapCat 单个调用也可能产生多次底层请求。

## 两个群独立使用

群 A 可以“90 天未发言、最久未发言优先、确认后清理”；群 B 可以“180 天未发言、群等级≤3、QQ 等级≤20、自动清理”。两者保护名单、人数和规则独立，执行节奏共用，账号额度合计。

QQ 群权限每次命令查询、确认执行前重新核对。不需要另填管理员名单。多个平台接入同一个 QQ 时拒绝执行；同一 QQ 不能在多个主机部署自动清理实例。

# 配置说明

配置只有三部分：总开关、每个群的规则、共用的执行节奏。平时只需修改群号、人数和未发言天数。更改配置后在 AstrBot 保存并重载插件，旧计划会失效。

## 每个群

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| 检查这个群 | 开 | 是否纳入定时检查；还需打开总开关 |
| 运行方式 | 仅预览 | 仅预览、确认后清理、自动清理 |
| 开始人数 | 490 | 人数达到此值才开始，不能超过实际容量 |
| 停止人数 | 470 | 必须低于开始人数；达到后停止 |
| 未发言天数 | 90 | 至少 7 天；最后发言、入群和本地观察到的活动取最新时间 |
| 新成员保护天数 | 30 | 至少 7 天；保护刚加入的人 |
| 先清理谁 | 最久未发言优先 | 在符合全部条件的候选中排序 |
| 群等级保护线 | 0 | 0 关闭；例如 10 表示等级≥10就保护 |
| 始终保留的 QQ | 空 | 每项一个 QQ，不用重复填写群主或管理员 |

人数达到开始线后形成一个清理周期，分批降至目标；中间自然退群也会减少需要清理的人数。周期最长 7 天，超过后需要重新达到开始线。配置改变后重新判断。

群号不可重复。开始/停止人数、天数、延迟等不合法时，插件明确指出配置位置并停止加载，不偷偷换成另一个值。

## 清理顺序

| 选项 | 优先级从左到右 |
| --- | --- |
| 最久未发言优先 | 最近活动时间由早到晚 |
| 群等级低优先 | 群等级由低到高 → 最近活动由早到晚 |
| QQ等级低优先 | QQ 等级由低到高 → 最近活动由早到晚 |
| 综合排序 | 未发言时长档位由大到小 → 群等级低 → QQ 等级低 → 最近活动由早到晚 |
| 自定义 | 使用你填写的顺序；最后用 QQ 号稳定排序 |

时长档位为 90、180、365 天：同一档内才比较下一项。自定义可逐项填写：`群等级`、`QQ等级`、`未发言天数`、`未发言时长档位`、`入群时间`。入群时间由早到晚排序。

例：“群等级低且长时间未发言，而且 QQ 等级也低”：未发言 90 天；“更多条件”中群等级上限 3、QQ 等级上限 20；顺序选群等级低优先。三个条件同时满足才成为候选。如果只希望 QQ 等级参与排序，不要设置 QQ 等级上限。

这是明确的多条件排序，没有隐藏分数，也不让 LLM 决定谁被移出。

## 更多条件（可以不填）

| 配置 | 默认 | 含义 |
| --- | --- | --- |
| 候选最高群等级 | 0 | 0 不限；正数表示只考虑≤该等级的人 |
| 候选最高 QQ 等级 | 0 | 同上；资料缺失不满足条件 |
| 保留专属头衔成员 | 开 | 头衔存在即保留；不能用接口固定的到期值判断过期 |
| 保留被禁言成员 | 开 | 避免把无法发言的人当作不活跃；状态不明也保留；全员禁言时暂缓整群清理 |
| 自定义顺序 | 空 | 选择自定义时填写；不能重复 |
| 机器人 QQ | 空 | 单 QQ 自动识别，多 QQ 接入才需要填写 |

所有开启的条件是“同时满足”。保护优先于候选条件，候选条件优先于排序。不提供任意布尔表达式编辑器，避免配置难以理解。

NapCat 的等级 0 可能是缺失值。规则依赖某种等级时，该等级未知的成员受到保留；不依赖时，不因缺失等级妨碍其他规则。群等级无法可靠补全时可使用最久未发言排序，并关闭群等级保护/上限。

QQ 等级每轮最多补查 20 人，候选资料缓存 7 天并绑定本次入群身份。在还存在未尝试补查的候选时不生成执行名单。全部尝试过后，对有效资料排序，仍然未知的成员保留。成功补查逐人保存进度，单个成员查询失败会暂时保留此人并缓存失败6小时，其他进度不会丢失。每次真正移出前再次查详情，缓存不能代替最后核验。

## 执行节奏

| 配置 | 默认 | 可填范围 |
| --- | --- | --- |
| 每批人数 | 5 | 1～10 |
| 每群最近 24 小时上限 | 20 | 1～100 |
| 每账号最近 24 小时上限 | 30 | 1～100；本插件各群合计 |
| 群内批次间隔 | 60 分钟 | 30～1440 |
| 每人操作前随机等待 | 30～90 秒 | 各 10～600；最小≤最大 |
| 每天允许执行时段 | 09:00～22:00 | 北京时间；0～24 全天，22～6 跨午夜 |

上限统计已提交请求，包括超时和结果不明。配额按滚动 24 小时计算，不是午夜清零。暂停、恢复、更新和重载均不清零。

确认计划有效 30 分钟。如果在有效期内无法满足时段、额度、批次间隔，计划过期，需要重新预览确认。手动确认不绕过任何等待条件。自动模式下一次检查自行生成新计划。

未暴露的内部限制：约 30～35 分钟检查一次，每个接入每小时最多 180 次读取（跨重载保留，后台最多使用120次，其余分别留给执行复核和管理员命令），读取间隔 1.5～3 秒，启动/恢复冷却 5～15 分钟。这些不是已验证的 QQ 安全频率；NapCat 单个调用也可能产生多次底层请求。

## 两个群独立使用

群 A 可以“90 天未发言、最久未发言优先、确认后清理”；群 B 可以“180 天未发言、群等级≤3、QQ 等级≤20、自动清理”。两者保护名单、人数和规则独立，执行节奏共用，账号额度合计。

QQ 群权限每次命令查询、确认执行前重新核对。不需要另填管理员名单。多个平台接入同一个 QQ 时拒绝执行；同一 QQ 不能在多个主机部署自动清理实例。

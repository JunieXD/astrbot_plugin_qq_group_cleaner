# 实现结构与扩展

v0.2.0 使用一张群规则表和一组共用节奏。使用者无需接触平台 ID、数据库、状态机、重试参数、资料来源表达式或复杂布尔编辑器。

## 模块职责

| 文件 | 职责 |
| --- | --- |
| `main.py` | AstrBot 注册、生命周期、事件与命令桥接 |
| `config.py` | 表单校验、不可变群策略、配置修订指纹 |
| `rules.py` | 纯数据模型、保护/候选判断、可解释排序 |
| `platform.py` | OneBot 形状校验、账号路由、读取限速、平台错误边界 |
| `store.py` | SQLite 单线程访问、计划、活动、保护、额度、写前意图 |
| `service.py` | 计划生成、有限资料补查、私聊授权、活动接入、调度 |
| `executor.py` | 唯一的移出执行路径与结果核验 |
| `commands.py` | 中文命令与使用者能理解的回复 |
| `resources.py` | 文件锁、大小/年龄轮转、存储健康检查 |

除入口外，业务模块不依赖 AstrBot 导入，可以独立测试。运行时无额外第三方依赖。

## 同一套规则贯穿预览与执行

1. 保护：自身、群主/管理员、身份未知、机器人标记、名单、近期入群、头衔、禁言。
2. 活动：有效平台最后发言时间必须存在，取平台发言、入群、本地正面活动三者最新时间。
3. 条件：未发言天数，以及可选的群等级和 QQ 等级上限，同时满足。
4. 排序：综合排序使用固定归一化后的加权得分；其他顺序使用有序字段。最后用QQ号稳定打破同序。
5. 执行：仅计划内成员，取人数缺口和每批上限的较小值，不补位、不放宽规则。

接口缺失、非法数值和等级 0 不替代成最低等级。规则用到缺失字段时返回具体保留原因。不用本地“没有消息”做负面推断，因此不需要让使用者理解活动覆盖窗口。

`ScoreWeights`作为不可变群策略的一部分，自动进入配置修订指纹。`Policy.sort_fields`统一计算资料依赖，权重0的等级维度不会触发排名补查；独立等级条件仍可要求该字段。纯函数`weighted_score`只接收已核验候选，使用固定量纲，不依赖实时群内分布或额外网络调用。`Decision.score`进入计划，预览理由显示分数；执行前仍复用`evaluate`检查保护，不临时换人。

## 状态与边界

计划绑定账号、群、接入平台、配置指纹、30分钟有效期和成员入群代次。确认码是不可预测的随机标识；权限另行通过当前群身份校验，不依赖仅持有码就执行。

自动检查按群轮转。每群一个工作锁，每个 QQ 一个执行锁。暂停和保护命令可以在随机等待中生效；普通查询和预览使用读取预算。代码不在数据库事务内等待网络。

已有审核/订阅插件存在兼容的共享协调器时，在其 `platform_id` 锁下复核与提交。不存在时独立运行，状态明确说明协调范围；不修改其他插件。自己仍按 QQ 身份合计额度。

成员消息、入群、退群、管理员变更只保存身份、时间、代次和去重摘要，不保存聊天正文。观察到的近期活动只加强保护。成员重新入群或详情中的入群时间变化会失效旧计划。

## 如何增加新需求

- 新增候选条件：在 `Policy`、配置校验和表单增加业务字段；在 `evaluate()` 返回条件和理由；添加未知值与边界测试。预览和最后核验自动复用。
- 新增排序：向排序字段映射增加有清晰方向的字段，或显式扩展评分维度；同时定义归一化、缺失值和零权重的行为，更新资料依赖与测试。
- 新增平台：实现与 `Adapter` 相同的只读与移出接口，保留账号绑定、明确失败、无写入重试和结果核验语义；先用模拟平台验证，再做受控真实联调。
- 新增资料补全：在计划阶段加入有界查询与缓存，执行前依然重新核验；不能扩大为全员陌生人资料扫描。
- 数据库变化：增加 `user_version` 的顺序迁移；遇到比自己新的版本停止，不创建新空库绕过审计。

## 当前没有实现的原方案扩展

任意 AND/OR 条件组、按比例触发、逐群时区、历史消息条数/活跃天数、荣誉保护、戳一戳与表情活动、导出、主动通知、跨主机执行协调都不在首版。首版用绝对人数、北京时间、有序规则与管理员主动查询满足主要使用流程。

这些扩展不以占位开关出现在配置页。后续增加时应优先复用规则/存储/平台接口，再考虑是否确实需要新的用户设置。

# 产品与规则设计

日期：2026-09-21。状态：待实施方案。本文中的按钮、命令、规则和状态均为规划，不表示已经实现。

## 1. 要解决的问题

群快满时，按管理员为该群明确配置的规则，逐步腾出名额。管理员能回答：何时开始、保护谁、谁进入候选、谁先被清理、最多清理多少、为什么没执行、如何立即停止。

不把“沉默”定义成没有价值，不自动评价聊天质量，不使用 LLM 决定移出成员，不提供无限制批量踢人、识别潜水阅读者、自动规避 QQ 检测等承诺。

首版交付应完整支持 observe（观察）、confirm（确认后执行）、auto（自动执行），默认禁用且选择 observe。三种模式使用同一个规则引擎和计划生成过程。observe 仅产生预览；confirm 消费管理员批准的特定名单；auto 消费通过全部检查的当前计划。切换模式不会让历史观察计划突然执行。

## 2. 管理员的使用流程

1. **绑定一个群**：给配置起名称，绑定 AstrBot 平台实例、机器人账号和群号；检测 bot 是否在群、是否有管理权限。
2. **查看数据能力**：列出群等级、QQ 等级、发言时间的有效率和未知率。缺字段时标记受影响的规则，不能默默关闭条件。
3. **选择预设并调整**：保守清理、优先低群等级、优先长时间不活跃三个预设只填入明确参数，没有隐藏行为。
4. **设置容量目标**：例如达到 490 人，清到 470 人；可选比例阈值。
5. **配置保护、候选、排序**：页面显示自然语言解释，例如“满足规则 A 或规则 B，且没有任何保护条件，才进入候选”。
6. **预览**：展示人数、需要腾出的名额、受保护人数、数据不足人数、候选人数、当前额度和计划前若干名。
7. **选择运行模式**：观察积累不等于自动授权；管理员自行选择 confirm 或 auto。启用 auto 是对以后符合规则的操作授权，不再每批要求确认。
8. **查看结果与停止**：所有计划可追溯。暂停立即阻止尚未发送的操作，不声称可以撤回已经发出的踢人请求。

管理命令只允许私聊使用，返回数据按群授权。群内误输入管理命令只提示私聊使用，不公开成员排名或待清理 QQ。首版不自动向候选成员逐个私聊、不发送群内点名倒计时，避免额外打扰和请求量。

## 3. 多群配置模型

每条群配置有稳定 `policy_id`、名称和 `(platform_id, self_id, group_id)`。同一账号下同一群只能有一条启用策略；换平台、换账号必须重新探测，不按“第一个在线 bot”猜目标。所有可调整业务阈值均按群保存，不共享不同群的候选和白名单。

配置面板基于 AstrBot 原生 `_conf_schema.json`：

- 全局：总开关、管理权限、账号额度、日志与存储、各分组默认值。
- 群策略列表：基础信息、触发方式、数据来源、保护参数、执行窗口、通知。
- 高级规则列表：每行属于某个 `policy_id`，按规则编号组成候选/保护条件。
- 排序列表：每行选择群策略、优先级、字段、方向和分档边界。

首版以标准 `object`、`template_list`、`list`、`options` 输入实现，不要求用户编写 Python 或提示词。复杂规则放在高级区域；普通用户选择预设后只改数字。配置引用、跨字段限制和能力检查由插件校验，不能假设 AstrBot 表单自带完整校验。动态下拉、拖拽排序和无限层级嵌套不是已确认的标准表单能力，不作为首版依赖。

继承以完整配置分组为单位：每组有“使用全局默认 / 自定义”选项；自定义后整个分组独立。展示生效值和来源，0 不代表继承。候选规则和排序使用“替换”语义，不能把全局规则和群规则暗中合并成更宽松的 OR。

精确字段、默认值、校验见 [configuration.md](configuration.md)。

## 4. 容量触发和停止

### 4.1 触发条件

- 绝对人数：当前人数 `>= trigger_count`。
- 占用比例：`trigger_count = ceil(max_member_count × trigger_percent / 100)`。
- `target_count` 为明确目标；比例模式目标采用 `floor(max_member_count × target_percent / 100)`。
- 必须满足 `0 < target_count < trigger_count <= max_member_count`；容量变化导致配置无效时暂停群策略并给出原因。
- 定时检查（默认 30 分钟加 0～5 分钟抖动），并合并入退群事件触发的检查（默认至少间隔 5 分钟）；事件只触发检查，不直接踢人。
- 人数超过阈值是创建“清理周期”的条件。周期创建后，只要高于目标可以分批继续，即使已经低于触发线；到达目标、周期过期（默认 7 天）或策略变更后关闭周期。

### 4.2 额度与收敛

每次先计算 `need = max(0, 当前人数 - 目标人数)`，本批数量取 need、候选数、群批额度、群滚动 24 小时额度、账号滚动 24 小时额度的最小值。需要 50 个名额不等于一次发送 50 次请求。

候选不足、数据不足、额度不足、执行窗口关闭分别显示；不会清理本不符合条件的成员。已有自然退群也计入腾出的空间。检查和执行之间人数变化时重新计算，计划数量只能缩小，不能自动替换成一批管理员没看过的人。

## 5. 成员规则的四层结构

### 5.1 固定保护，不能被业务规则取消

群主、管理员、机器人自身、此群策略的授权操作人、权限无法确认者、成员身份/入群代次无法确认者不可自动移出。白名单优先于一切候选规则；清理不提供“强制无视保护”按钮。

数据源不健康、账号离线、计划过期、权限丢失、审计无法落盘也不执行。规则配置不能解除这些工程约束。

### 5.2 按群配置的保护

- 永久白名单：明确 QQ 列表。
- 临时白名单：QQ、截止日期、原因、设置者；过期只撤销保护，不立即清理。
- 新人保护：入群不足 N 天，默认 30 天。
- 最近活动保护：距可信最后活动不足 N 天，默认 30 天。
- 群等级保护：达到 L 级，默认关闭，启用需核验该群字段有效。
- QQ 等级保护：达到 Q 级，默认关闭，启用产生按需查询成本。
- 专属头衔保护：默认关闭；可选非空头衔或指定头衔名单。平台头衔到期字段可能不可用，不据 `title_expire_time=0` 自行解释为永久身份。
- 其他机器人保护：`is_robot=true` 或明确 bot 白名单；`false` 不证明一定是真人。
- 当前禁言成员保护：默认开启；不知道禁言状态时保护。全员禁言时默认暂停该群清理，解除后保护 7 天。不能据“解除时未禁言”证明过去不活跃期没有被禁言。
- 自定义保护：例如“群等级达到 8 且入群满 180 天”，使用与候选相同的条件表。

启用的保护规则结果为 unknown 时，保护该成员并解释“无法排除豁免”；不会把未知当成 false。

### 5.3 候选条件：哪些成员有资格被考虑

基础门槛默认入群满 30 天、可信不活跃天数至少 90 天。基础门槛始终与高级规则 AND，高级规则不能绕过门槛。

可选两种配置模式：

- `simple`：不活跃门槛，再加可选群等级上限、QQ 等级上限；已开启条件全部满足。
- `rules`：基础门槛，再满足若干规则组中的任意一组。一个规则组内所有条件必须满足。

例：

```text
基础门槛：入群至少 30 天，未活动至少 90 天
并且：
  A：未活动至少 180 天 且 群等级小于 8
  或
  B：未活动至少 90 天 且 群等级小于 3 且 QQ等级小于 32
```

支持限定字段、限定运算符的条件表，不接受 `eval`、用户脚本、任意 SQL、正则代码执行或 LLM 输出。具体字段见配置说明。AND/OR 使用三值逻辑：`false AND unknown = false`、`true OR unknown = true`，只有候选最终结果 true 才入选；“未知”不能转换成最低分。

没有规则组、规则重复、单位错误均为配置错误。不能因为配置解析失败退回“清理所有普通成员”。

### 5.4 排序：谁先清理

采用可配置的多字段顺序排序，前一个字段优先级高；不默认使用难解释的加权总分。

提供三个预设，所有排序均只作用于已经符合条件的候选：

| 预设 | 排序顺序 |
| --- | --- |
| 保守清理（默认） | 不活跃分档降序 → 群等级升序 → 不活跃天数降序 |
| 优先低群等级 | 群等级升序 → 不活跃天数降序 → QQ等级升序（需主动启用） |
| 优先最长不活跃 | 不活跃天数降序 → 群等级升序 |

默认不活跃档位边界 `[90, 180, 365]`，使用 `>=` 下界，180 天进入第二档；界面明确显示范围。完全同序时按稳定成员 ID 排序，保证预览复现；随机只用于操作时间，不用于选谁。

排序依赖的字段缺失时默认暂缓该成员，可选择“未知值排最后”，但必须在预览中显示。候选和保护条件的未知处理不能被这个选项改变。全群排序字段失效时不能悄悄把它从排序链移除，应阻止执行并提示管理员显式改规则。

QQ 等级可设为主要条件或主要排序字段，但需要把相应候选范围查全才能声称完成排序。查询预算不足则计划处于数据补充中；不把未查询者当低等级，也不依据前几名查询结果代表所有成员。

## 6. 活动的定义和观测边界

默认 `platform_speech`：有效平台最后发言时间与本地实际收到的群消息时间取较新者。文本、图片、语音、视频、文件等实际群消息都算发言；不评价内容是否“有价值”。撤回不撤销已观察到的活动。

可选 `observed_events`：管理员明确选择群消息之外是否把戳一戳、表情回应等计为活动。只有本机版本提供可识别 actor、group、time 的事件才启用；无法定位发起人的事件不记账。相关事件历史无法完整回溯，必须有连续观测覆盖。

本地另可累计滚动窗口发言条数、活跃天数，用于高级规则或保护；这类指标只反映插件实际收到的事件。聊天正文不落盘。最小正文长度、关键词过滤、刷屏质量评分不进入首版，避免把内容审核混进容量管理。

**零时间 ≠ 从未发言。** 未知最后发言者可选择持续观测满门槛后再候选，起点是“本次入群、首次可靠见到该成员、最后一次观测中断结束”三者的最晚时间；不能回溯到插件安装前猜测沉默时长。掉线、会话过滤、插件停用、队列溢出均形成覆盖缺口。

群等级等信息无法证明真实贡献；QQ 等级无法证明账号可信度；没有 API 能证明潜水阅读、手机在线、其他群活跃、真实学籍或完整历史贡献。

## 7. 预览、确认和执行

预览只读，默认展示前 20 名，每人包含：脱敏标识、成员入群代次、入群时长、各活动时间及来源、等级有效性、命中的规则、排序键、保护检查结论。授权私聊可查看单人成因和完整标识。

命令规划：

| 命令 | 作用 |
| --- | --- |
| `/qgclean status <策略>` | 模式、人数、周期、额度、暂停原因、数据健康 |
| `/qgclean check <策略>` | 受限频率的只读能力诊断 |
| `/qgclean preview <策略>` | 创建预览，不改变当前运行模式 |
| `/qgclean explain <策略> <QQ>` | 为什么被保护、待确认或候选 |
| `/qgclean confirm <计划ID> <确认码>` | 仅 confirm 模式授权特定名单，单次消费 |
| `/qgclean cancel <计划ID>` | 取消待执行计划 |
| `/qgclean pause <策略或all>` | 紧急暂停；配置和进度持久保存 |
| `/qgclean resume <策略>` | 检查权限及能力后恢复，不复用过期名单 |
| `/qgclean protect <策略> <QQ> <期限> <原因>` | 设置业务白名单；永久/临时明确区分 |
| `/qgclean unprotect <策略> <QQ>` | 撤销业务保护，不能解除固定保护 |
| `/qgclean history <策略>` | 分页查询计划与操作结果 |
| `/qgclean export <策略> <计划ID>` | 生成本地受控导出；交付方式需受权限与发送预算约束 |

用户必须是 AstrBot 主管理员，或在该策略允许名单内且当前为该群管理员。群管理员身份不意味着可以操作其他群；AstrBot `ADMIN` 过滤器仅代表框架权限，仍要插件校验群范围。`all` 只对主管理员开放。机器账号、群号和计划绑定验证不能依赖私聊 session 推断。

计划含规则版本、数据时间、到期时间和成员名单；默认 30 分钟过期。确认码仅用于防误选、重复提交，不能代替权限校验。名单提交后只能减少，增加/替换成员必须重新生成计划。配置变化、白名单变化、关键数据变化使计划失效或剔除相关成员。

执行前在随机等待结束后重查角色、入群代次、等级、活动、人数和全局暂停；每个成员单独发送请求。检测到新发言、已退群、重新入群、被提为管理员立即跳过。即时复查和发送之间仍存在平台不可原子化的短窗口，不能宣称绝对消除竞态。

默认 `reject_add_request=false`，普通移出允许以后重新申请。禁止再次申请属于不同的处罚目的，不提供为常规容量清理自动开启的选项。bot 无法保证把成员自动拉回，因此不提供“撤销踢人”的虚假承诺。

## 8. 首版范围和后续扩展

首版：三种模式、多群独立配置、基础/规则组筛选、词典序与分档排序、数据未知保护、按需 QQ 等级、活动记录、临时保护、持久化执行、日志轮转、完整审计和只读诊断。

后续：独立可视化规则编辑器、可审阅的加权分数模式、可选群公告提醒、多实例跨主机协调。首版不承诺这些能力。不能为了后续扩展而预先暴露不生效的配置。

在实际群上第一次执行前必须完成工程文档中的受控测试群验收；本次调研没有移出任何人、发消息或改变群设置。

# 现实场景审查：v0.1.1

审查以已交付的 v0.1.0 为起点，重点检查缓存、权限、异步任务、连接变化和持久状态之间的交互。下表是已修复的具体问题，均有隔离回归测试。

| 现实场景 | 原问题 | 修复后的行为 |
| --- | --- | --- |
| 已收到退群通知，NapCat随后仍返回旧名单 | 旧名单把成员重新记为在群，创建新代次，可能失去同次入群防重 | 保留离群状态，旧名单标记身份冲突；只有匹配的新入群证据才建立新代次 |
| 同一成员入群时间在有效值、空值和旧值之间变化 | 每次变化都新建代次 | 入群时间不回退；缺失/冲突保留成员；向后的修正也重新开始活动保护 |
| 列表查到近期发言，后续详情缓存更旧 | 平台查到的近期活动没有持久保存，后续可能错误符合不活跃条件 | 平台和实时活动证据合并取最大值，跨重载保持 |
| 已收到撤管理员通知，接口仍显示管理员 | 旧缓存可能继续授权命令或确认 | 已知撤权/退群阻止授权，确认人和机器人执行前也检查；升权通知只加强保护，不能单独授权 |
| 补查第十名成员时UID查询失败 | 前九名的进度丢失，下一次重复查且可能一直停在同一人 | 每名成功立即存进度；失败暂存6小时，暂缓当次任务，后续可继续其他成员 |
| 大群补查超过一天 | 先查到的资料已经过期，可能永远补不齐 | 资料缓存7天；执行前仍查详情，缺失成员不按0级处理 |
| 一个群处于数分钟等待 | 单一后台任务阻塞其他群，甚至耗掉其他计划有效期 | 最多4个群独立检查，按到期顺序调度；账号执行锁仍阻止并发移出 |
| 后台读完全部额度 | 管理员授权、暂停、核对也无法调用接口 | 120次后台预算、30次执行复核储备、30次管理员储备，总计180次/小时；预算跨重载保存 |
| 重连或替换接入发生在随机等待/最后排队中 | 同账号同群的旧计划仍可能继续使用 | 计划绑定连接代次与接入集合；变化作废，恢复冷却；最后核验超过30秒取消 |
| 已识别的另一个QQ掉线 | 路由扫描失败连带阻塞正常账号 | 已明确不同身份的反向WS接入可独立工作；未知或变化的身份仍按歧义暂停 |
| 一个接入连了多个QQ，或新增重复账号连接 | 依赖aiocqhttp隐式路由，可能出现歧义 | 明确传入QQ身份，拒绝单接入多QQ；执行前检查新增重复连接 |
| 提交意图后中断，还未来得及写账号暂停 | 仅检查本群未决记录的边界可能让另一群继续 | 执行入口和写前事务都检查整个账号的未决操作 |
| 活动/保护在最终检查与写前提交之间变化 | 检查和意图记录之间仍有本地并发窗口 | 事务再次核对已授权成员、代次、活动和保护，真正发送前再检查事件版本 |
| 其他群管理员执行恢复 | 可能解除不属于其管理范围的账号异常暂停 | 暂停绑定来源群，必须由来源群管理员处理并恢复 |
| 初始化过程中被取消，或关闭数据库/日志失败 | 文件锁和连接可能残留，影响下一次重载 | 取消时清理；各类关闭均用finally释放后续资源；停止不等待调用者自身 |

没有增加新的用户配置项。原有规则和保护名单继续有效；更新重载后需要重新生成确认计划。

验证使用模拟适配器和临时数据库，不调用真实QQ移出、发送或设置接口。Windows/Linux持续集成检查相同场景。

仍存在平台本身的边界：NapCat缓存没有可验证的版本号，OneBot没有原子条件移出；未送达的群事件、两次查询之间不可观察的QQ状态变化，以及最后请求到达服务器之前的新发言/权限变化无法全部消除。遇到可观察的冲突会保留成员或停止，不把模拟测试当作真实群联调证明。

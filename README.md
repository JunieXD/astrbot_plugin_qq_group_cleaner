# QQ 群成员清理

按群容量、成员不活跃时间和管理员规则生成清理计划的 AstrBot 插件项目。

**当前为设计阶段（v0.0.0）：已完成能力核验和方案文档，尚无运行入口，不会执行成员移出。请勿作为已实现插件安装。**

## 方案入口

- [产品与规则设计](docs/design.md)：使用流程、豁免、条件组合、排序、计划及确认机制。
- [AstrBot / NapCat 能力核验](docs/capabilities.md)：2026-09-21 本机只读实测、源码证据和无法保证的能力。
- [完整配置说明](docs/configuration.md)：配置分组、默认值、单位、继承、校验、不同群的示例。
- [工程实现与验收计划](docs/engineering.md)：状态机、并发、未知结果、频率控制、日志轮转、数据保留和测试。
- [配置示例](examples/policies.json)：包含两个虚构群的设计态配置；不是当前可安装的 `_conf_schema.json`。

## 核心原则

1. 群人数达到触发线后启动，降到目标人数后停止；候选不足不放宽规则。
2. 群主、管理员、机器人自身不可清理；其他保护规则每群配置。
3. 豁免、候选条件、排序互相独立；未知数据不会自动变成低等级或长期未发言。
4. 每批有名单、解释和数量上限；执行前重新核对，执行结果不明不重复踢人。
5. 随机延迟配合账号串行、额度和失败暂停；不承诺避免 QQ 风控。

规划目标平台为 AstrBot 的 `aiocqhttp`（OneBot v11）接入 NapCat。已核验基线：AstrBot 4.26.2、NapCat 4.18.19、Windows x64 QQ 9.9.26-44498；这些是研究基线，不是完整兼容性测试声明。

仓库仅包含设计、虚构示例和汇总证据，不包含实际群号、成员明细、账号密钥或运行日志。

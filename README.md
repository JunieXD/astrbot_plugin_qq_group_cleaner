# QQ 群成员清理

群人数达到设定值后，按未发言时间、群等级和 QQ 等级筛选成员，分批腾出空间。每个群单独设置，默认只预览。

适用于 **AstrBot 4.26.2+ / aiocqhttp / NapCat**。能力核验基线为 NapCat 4.18.19；其他 OneBot 实现需要提供 NapCat 的群详情接口。

## 三步开始

1. 在 AstrBot 插件管理中，从仓库链接安装：`https://github.com/JunieXD/astrbot_plugin_qq_group_cleaner`。
2. 打开插件配置，在“要管理的群”添加群号，填写“开始人数”“停止人数”“未发言天数”。第一次保持“仅预览”，其余默认即可。
3. 用该群的群主或管理员 QQ **私聊机器人**：`/群清理 预览 群号`，查看候选和保留原因。

确认规则符合预期后，打开“启用定时检查”，把该群改成“确认后清理”或“自动清理”。机器人需要是这个群的管理员。

| 运行方式 | 怎么使用 |
| --- | --- |
| 仅预览 | 只筛选，不移出成员；私聊预览查看名单 |
| 确认后清理 | 私聊预览，复制回复中的确认命令，只执行这批名单 |
| 自动清理 | 约每 30～35 分钟检查，人数达到条件后分批执行 |

不开定时检查也可以手动预览。**预览命令不会直接执行移出**，即使该群配置为自动模式；自动任务按自己的检查周期重新生成执行计划。

## 配置示例

一个 500 人群，希望快满时腾出一些位置：

- 开始人数：490；停止人数：470。
- 至少 90 天未发言，新成员保护 30 天。
- 清理顺序：最久未发言优先。
- 群等级达到 10 就保护；如果不使用等级保护，保持 0。
- 重要成员填写在“始终保留的 QQ 号”中。

如果你希望“优先群等级低，再看多久没发言，最后看 QQ 等级”，选择“自定义”，在“更多条件 → 自定义清理顺序”依次填 `群等级`、`未发言天数`、`QQ等级`。无需写公式或提示词。

等级缺失会保留成员；NapCat 返回的等级 0 可能表示没有读到数据，所以不能按低等级处理。首次使用等级条件，建议用“解释”命令核对几名已知成员。

## 常用命令

所有命令只接受该群当前群主或管理员的私聊；AstrBot 的全局管理员身份不能代替群管理权限。以下“群号”“QQ号”需要替换。

| 命令 | 用途 |
| --- | --- |
| `/群清理` | 查看帮助 |
| `/群清理 预览 群号` | 查看本批名单和保留原因 |
| `/群清理 确认 群号 确认码` | 确认预览中的这一批，有效期 30 分钟 |
| `/群清理 状态 群号` | 查看人数、模式、额度、资料补查和暂停原因 |
| `/群清理 暂停 群号` | 停止尚未提交的操作 |
| `/群清理 恢复 群号` | 丢弃旧计划，冷却 5～15 分钟后重新检查 |
| `/群清理 解释 群号 QQ号` | 查看这个人符合候选条件或被保留的原因 |
| `/群清理 保护 群号 QQ号` | 永久保护；末尾加天数可临时保护 |
| `/群清理 取消保护 群号 QQ号` | 取消命令保护，留 7 天缓冲；配置保护需在配置页修改 |
| `/群清理 历史 群号` | 最近 20 条已提交操作及结果 |
| `/群清理 核对 群号` | 只读核对结果不明的操作，不会重发移出 |
| `/群清理 保留 群号 QQ号` | 将该成员的未决操作记为人工保留，并永久保护此人 |

`/qgclean` 是 `/群清理` 的别名。如果自定义了 AstrBot 唤醒前缀，请使用对应前缀。

## 执行中的保护

- 群主、管理员、机器人自身始终保留；默认也保留有专属头衔、正在禁言和平台标记为机器人的成员。
- 新成员、保护名单、近期发言者不会因低等级而变成候选；开启禁言保护时，全员禁言也会暂缓整个群的清理。
- 每次随机等待后，重新核对角色、入群身份、活动、保护名单和人数。变化只跳过，不补进未经确认的人。
- 默认每批最多 5 人、每群最近 24 小时最多 20 人、每个 QQ 合计最多 30 人；群内两批至少隔 60 分钟，每人操作前等待 30～90 秒，北京时间 09:00～22:00 允许执行。“执行节奏”可调整这些值。
- 只做普通移出，传入 `reject_add_request=false`；能否立即重新申请仍由 QQ 群策略决定。
- 接口返回成功还会核验。如果超时、断线或无法确认离群，就停止账号后续清理；重启不会清零额度，也不会自动重发。

没有合格候选时，不会放宽规则凑人数。随机间隔用于减少集中请求，**不能保证避免 QQ 风控**。

## 出现问题时

先私聊查询“状态”和“历史”。有结果不明的记录时，使用“核对”；仍无法确认且决定不再处理此人，可使用“保留”，再“恢复”。这不会撤销已经发出的移出请求。

插件数据在 AstrBot 的 `data/plugin_data/astrbot_plugin_qq_group_cleaner/`：

- `state.sqlite3`：计划、保护、额度、活动时间和操作审计。不要通过删除它解决重复执行问题。
- `logs/cleaner.log`：运行日志，10 MiB 轮转，最多 7 个归档，超过 14 天的归档清理。

不保存聊天正文，不调用 LLM，不需要 WebUI/OpenAPI 密钥，不主动发群内名单或私聊通知。

## 当前边界

v0.1.0 已实现三种模式、规则、计划、受控执行和恢复流程，并配有隔离测试。尚未在真实 QQ 群执行移出，也没有在本机正式实例安装或启用；兼容性依据为源码、先前只读 API 核验和模拟测试。Windows/Linux 自动测试由 GitHub Actions 运行，结果见仓库 Actions。

QQ 不提供阅读/潜水时长、完整历史贡献或可靠的“从未发言”证明。插件不把本地没有收到消息当作长期不活跃证据。NapCat 的缓存与无原子条件移出接口意味着，最后一次核验和服务器实际执行之间仍有无法完全消除的竞态。
